## Section « Infos »

Je développe des solutions d’automatisation destinées à simplifier les processus administratifs et à fiabiliser le traitement des dossiers.

Dans le cadre d’un projet personnel orienté métier, j’ai conçu un flux complet capable de recevoir des demandes par webhook ou fichier CSV, d’analyser les informations reçues, de contrôler la complétude d’un dossier, de détecter les éléments manquants, de prioriser les demandes et d’enregistrer les résultats dans une base de données.

Le projet s’appuie notamment sur :

- n8n pour orchestrer les workflows et connecter les services ;
- FastAPI et Python pour exposer la logique métier ;
- Supabase/PostgreSQL pour structurer les dossiers, contrôles et historiques ;
- Postman pour tester les requêtes et les réponses ;
- des webhooks, API REST, données JSON et fichiers CSV.

J’ai également travaillé sur la gestion des erreurs, la traçabilité des actions et l’idempotence afin d’éviter la création de doublons lors d’un nouvel envoi identique.

Je souhaite maintenant renforcer ces compétences dans un environnement professionnel, notamment dans le cadre d’une POEI ou d’une opportunité junior en automatisation, intégration d’API, support applicatif ou développement Python.

Mon approche : partir d’un besoin concret, construire un pilote limité, tester avec des données maîtrisées, documenter le fonctionnement et mesurer les résultats avant d’élargir le périmètre.

## Expérience — à ajouter comme projet

### Projet personnel — Automatisation de processus administratifs

**Projet personnel · 2026**

Conception d’un prototype d’automatisation pour la réception, le contrôle et l’orientation de dossiers administratifs.

**Réalisations :**

- création de workflows n8n avec webhooks et traitement CSV ;
- développement d’API FastAPI pour appliquer la logique métier ;
- contrôle de la complétude et génération de messages de relance ;
- stockage des lots, dossiers, contrôles et actions dans Supabase/PostgreSQL ;
- mise en place d’une clé d’idempotence contre les doublons ;
- tests des endpoints avec Postman ;
- documentation du projet et préparation d’un déploiement progressif.

**Résultat démontré :** un second envoi identique retourne le même identifiant de lot sans créer de nouvelle ligne en base.

**Précision :** prototype réalisé dans un environnement local de démonstration, non présenté comme une solution déjà déployée chez un client.
